# DynamicEmb on GB300

GB300 uses a Grace ARM CPU (`linux/arm64`) and CUDA compute capability **10.3**
(`SM103`). It is distinct from GB200/B200 (`SM100`). See NVIDIA's
[GPU table](https://developer.nvidia.com/cuda/gpus) and
[GB300 software stack](https://docs.nvidia.com/dgx/dgxgb300nvl72-release-notes/system-libraries-tools-drivers.html).
The stack page lists driver 580.167.08, CUDA Toolkit 13.0.2 and cuDNN 9.18.1;
it refers PyTorch users to NGC, rather than specifying a PyTorch minimum.

## Dependency set

Reuse `docker/Dockerfile`'s version-coupled stack instead of independently
upgrading `torch` with pip:

| Component | Build input |
| --- | --- |
| NGC PyTorch | `nvcr.io/nvidia/pytorch:26.07-py3`, manifest index pinned by digest in `docker/Dockerfile` |
| PyTorch / Toolkit | 2.13.0a0 / CUDA 13.3.1, supplied by NGC |
| FBGEMM_GPU | `v1.8.0`, source build on ARM, including `10.3` |
| TorchRec | `v1.8.0-rc1`, including its declared Python dependencies |
| TensorDict / pyvers / cloudpickle / orjson | `0.15.4` / `0.2.3` / `3.1.2` / `3.13.0` |
| DynamicEmb extension / eviction SASS / eviction LTO-IR | `DEMB_ARCHS=103` |

The [NGC 26.07 release notes](https://docs.nvidia.com/deeplearning/frameworks/pytorch-release-notes/rel-26-07.html)
describe the selected PyTorch/Toolkit versions and link their driver requirements.
A driver meeting the older GB300 stack alone is not proof that it can run a newer
NGC container; run the checks below on the actual host. Do not replace NGC's
PyTorch while installing TorchRec or FBGEMM. TorchRec dependency resolution uses
exact version constraints for the installed NGC PyTorch and source-built FBGEMM,
so pip resolves Python dependencies without replacing either native package.

`docker/Dockerfile.pyt_build` is a legacy x86 Torch 2.6/CUDA 12.6 environment,
not a GB300 build. The `dynamicemb` target below builds the current checkout;
it does not clone a moving repository HEAD or build HSTU/Triton services.

## Build

Run from the repository root on an ARM builder. The default NGC image is pinned
to a multi-architecture manifest digest. When overriding it, also pass an immutable
digest via `--build-arg BASE_IMAGE=...@sha256:...`.

```bash
docker build --platform linux/arm64 -f docker/Dockerfile \
  --target dynamicemb --build-arg DEMB_ARCHS=103 \
  --build-arg FBGEMM_CUDA_ARCH_LIST=10.3 \
  --build-arg MAX_JOBS=4 -t dynamicemb:gb300 .
```

ARM always compiles FBGEMM from source. For a B300 x86 builder, additionally
pass `--platform linux/amd64 --build-arg FBGEMM_BUILD_FROM_SOURCE=1` to avoid
assuming the prebuilt FBGEMM wheel contains SM103 kernels. This does not
constitute GB300/Grace acceptance.

Without `DEMB_ARCHS`, setup selects supported targets from the actual nvcc's
`--list-gpu-code`, including SM103 when available. An explicit unsupported or
empty override fails. The inference CMake build uses the same compiler-target
discovery and respects explicit `CMAKE_CUDA_ARCHITECTURES`, `CUDAARCHS`, or `SM`.

## Verify on GB300

The image build checks distribution metadata, installed module/artifact paths,
the compiler, PyTorch CUDA version, SM103 compiler support and cuDNN. It imports
CPU-safe TensorDict, pyre_extensions and torchmetrics before compiling DynamicEmb
to check their Python dependencies, including pyvers and cloudpickle. CPU builders
do not need host NVIDIA driver libraries such as NVML. Actual FBGEMM, TorchRec and
DynamicEmb library loading is checked on the GB300, together with GPU execution.

```bash
docker run --rm --gpus all --ipc=host dynamicemb:gb300 \
  python3 corelib/dynamicemb/test/check_gb300.py

docker run --rm --gpus all --ipc=host dynamicemb:gb300 bash -ec '
  cd corelib/dynamicemb
  python3 -m pytest -q test/unit_tests/table_operation/test_multitable_ref_counter.py \
    test/unit_tests/table_operation/test_lru_lfu.py --junitxml=/tmp/gb300.xml
  python3 -m torch.distributed.run --standalone --nproc_per_node=1 \
    test/unit_tests/test_sequence_embedding_bw.py --batch_size 128
  python3 -m torch.distributed.run --standalone --nproc_per_node=1 \
    test/unit_tests/test_pooled_embedding_bw.py --batch_size 128
'
```

The smoke requires an ARM host and a real SM103 GPU. It executes FBGEMM's CUDA
cumsum operator and DynamicEmb insert/lookup and validates their outputs.
The table tests exercise default eviction cubins and custom-score LTO linking;
check JUnit for failures, errors and skips, not just pytest's exit code.
The sequence backward program compares SGD updates against key occurrence
counts. The pooled backward program executes forward/backward and checks output
shapes; it does not compare gradients or updated values with a reference.
Multi-GPU/NCCL, checkpoint scale and performance require separate runs; these
commands do not establish those claims.

For the optional inference library, build on the same dependency set:

```bash
cmake -S corelib/dynamicemb -B /tmp/dynamicemb-inference \
  -DCMAKE_CUDA_ARCHITECTURES=103
cmake --build /tmp/dynamicemb-inference -j4
python3 -c 'import torch; torch.ops.load_library("/tmp/dynamicemb-inference/inference_emb_ops.so")'
```
